# XR Bibliometrics — Reproducible Analysis Pipeline

**Paper**: *Extended Reality (XR) in Education: A Systematic Bibliometric Analysis*
**Journal**: Computers & Education

This repository contains the reproducible analysis pipeline for the
bibliometric study of Scopus records retrieved with immersive-technology terms
(VR, AR, MR/XR and combinations), 1991–2025. After XR/year screening, a
deterministic education-eligibility algorithm searches Title, Abstract, and
Author Keywords. Inclusion requires an explicit education/training cue; the
algorithm does not use Index Keywords or human adjudication. The final corpus is
defined by the stage counts and record-level trace in `results/`.

## Scopus Data Cleaning Pipeline

The raw Scopus export (`scopus_raw.csv`, 12,505 records) is processed through
sequential stages before analysis:

| Stage | Operation | Description |
|-------|-----------|-------------|
| 0 | Load | Read raw Scopus CSV with UTF-8-BOM encoding |
| 1 | Column normalization | Strip BOM character and whitespace from column names |
| 2 | Exact deduplication | Remove rows where all fields are identical |
| 3 | DOI deduplication | Normalize DOI and retain the occurrence with the richest selected metadata |
| 4 | Title deduplication | Match exact normalized non-empty title + year + first-author ID/name; preserve records with distinct DOIs |
| 5 | Essential metadata filter | Exclude records missing Title, Year, or Source title |
| 6 | Thematic screening | Retain only records containing XR-related terms in Title + Abstract + Author Keywords |
| 7 | Year filter | Retain publication years 1991–2025 inclusive |
| 8 | Education-eligibility algorithm | Include if Title, Abstract, or Author Keywords has a qualifying explicit education/training cue; otherwise exclude. Clinical-use cues do not veto an education cue |
| 9 | Classification eligibility | Retain algorithmically eligible records assigned to one canonical technology category |

The stage-by-stage record counts are saved to `results/pipeline_report.csv`,
`results/table_A0_pipeline_audit.csv`, and `results/fig_A0_pipeline_audit.png`.
The current export's final count is written in the audit files. Stage 4 is exact
matching after title normalization plus year and first author, not fuzzy title
similarity; distinct non-empty DOIs are retained. Within duplicate DOI/title
groups, the row with the richest non-empty bibliographic metadata is kept. The export has no search
date/provenance field, so this code cannot establish whether 2025 coverage is
complete. Do not interpret the last-year count as complete-year coverage
without the Scopus query and retrieval date.

### Education-Eligibility Algorithm

The screen searches only Title, Abstract, and Author Keywords (not Index Keywords), using case-insensitive matching against the prespecified dictionary in `working_area/utils/education_screen.py`.
Explicit teaching, education, learner/student, curriculum, learning-outcome, and
training cues mean include, including health-professions training; clinical-use
terminology is recorded for audit but cannot override an education cue. No
qualifying education cue means exclude. Generic computational phrases such as
“machine learning” and “training data” are insufficient without another
substantive education cue. There is no manual queue or inter-rater calculation
in this binary algorithm. Counts, matched cues, and the complete specification
are exported in `table_A11_education_screen_counts.csv`,
`table_A11_education_screen_trace.csv`, and
`table_A11_algorithm_specification.csv`. See
`results/education_screen_paper_methods.md` for copy-ready methods text and
the lexical-screen limitation.

## Technology Classification Scheme

The canonical classification logic is defined **once** in `utils/classifier.py`
and imported by all analysis modules. This addresses the methodological
inconsistency flagged by reviewers (different scripts using different rules).

### Four Categories (aligned with manuscript)

| Category | Definition |
|----------|-----------|
| **VR** — Virtual Reality | Records containing VR-specific terms (virtual reality, VR, HMD, Oculus, HTC Vive, CAVE, 360 video…) with NO AR or MR/XR signals |
| **AR** — Augmented Reality | Records containing AR-specific terms (augmented reality, AR, smart glasses, HUD…) with NO VR or MR/XR signals |
| **MR/XR** — Mixed/Extended Reality | Records containing any MR/XR term (mixed reality, extended reality, XR, MR, HoloLens, Magic Leap, spatial computing…) regardless of other signals |
| **Hybrid/Multi-technology** | Records co-mentioning VR **and** AR terms, with NO MR/XR signal — this is the manuscript definition, NOT VR+AR→MR/XR |

### Priority Order

```
1. EXCLUDE  → if EXCLUSION_TERMS present AND no explicit VR/AR/MR/XR term
2. MR/XR    → any MR/XR term present
3. Hybrid   → VR terms AND AR terms present (but not MR/XR)
4. AR       → only AR terms
5. VR       → only VR terms
6. None     → unclassifiable
```

### Fields Searched

All four fields are concatenated for classification:
- `Title`
- `Abstract`
- `Author Keywords`
- `Index Keywords`

### Important Design Decisions

- **`immersive` alone does NOT trigger VR.** The term appears in "immersive learning"
  and "immersive education" contexts that are not VR-specific. Explicit technology
  terms such as "virtual reality" do trigger VR; hardware is not required when the
  technology is explicitly named.

- **`metaverse`, `digital twin`, `passthrough` are NOT MR/XR terms.** These are
  broader concepts that appear in non-XR contexts and are excluded from the classifier.

- **MR/XR is a terminological category, not an ontological equivalence.** Mixed Reality
  and Extended Reality are grouped because they overlap heavily in the Scopus corpus.
  This does not claim MR and XR are conceptually equivalent.

## Technical vs Pedagogical Orientation

The `classify_orientation()` function in `utils/classifier.py` classifies each
record as **Technical** or **Pedagogical** based on the dominant keyword signal
in Title + Abstract + Author Keywords.

This classifier was previously absent from the repository and is required to
reproduce Figure 2 and the RQ4 analysis in the manuscript.

This is a deterministic keyword score, not human coding: each distinct
dictionary term contributes one point if present in Title + Abstract + Author
Keywords, and ties are assigned Pedagogical. In the current run, 9,472 of
9,535 classified records (99.3%) receive the Pedagogical label. This imbalance
means the orientation figure is exploratory; the A10 worksheet is an optional
validation aid and is not used to define the education-eligibility corpus.

## Analysis Modules

| Module | ID | Output | Manuscript correspondence |
|--------|----|--------|--------------------------|
| Publication Growth | A1 | `fig_A1_publication_growth.png`, `table_A1_yearly_stats.csv` | RQ1 growth figures |
| Orientation Analysis | A2 | `fig_A2_orientation_*.png`, `table_A2_orientation_counts.csv` | Figure 2, RQ4 |
| Author Analysis | A3 | `fig_A3_top_authors_*.png`, `table_A3_author_stats.csv` | Author productivity tables |
| Country Collaboration | A4 | `fig_A4_scp_mcp*.png`, `table_A4_country_collab.csv` | SCP/MCP analysis |
| Bradford Zones | A5 | `fig_A5_bradford_*.png`, `table_A5_bradford_zones.csv` | Source concentration |
| Bibliometric Table | A6 | `table_A6_bibliometric_main.csv/.md` | Table 1 |
| Classification audit | A10 | `table_A10_classification_trace.csv`, `table_A10_human_validation_worksheet.csv` | Technology/orientation rule trace |
| Education-eligibility algorithm | A11 | `table_A11_education_screen_trace.csv`, `table_A11_education_screen_counts.csv`, `table_A11_algorithm_specification.csv` | Binary lexical eligibility decision and record-level audit trail |

Each A8 network is exported as static PNG/PDF figures. Node area represents
unweighted degree (number of direct links); node color represents Louvain
community, and edge width represents co-occurrence/collaboration frequency.
Force-directed layouts show every linked component; author co-citation isolates
remain in the accompanying node table, as they have no link to draw. The author
institution map displays up to 60 institutions with at least 8 corpus records;
a collaboration edge is retained when two institutions share at least one
record. The author
collaboration network is a co-authorship network built from Scopus
`Authors` entries separated by semicolons. A separate, actual author
co-citation network is computed from the `References` field using the cited
first author. It plots all authors cited by at least 15 corpus documents that
have at least one link co-cited in 2 or more corpus documents;
node, edge, and threshold-sensitivity tables are exported. The Scopus export has cited references for 9,229 of the
9,535 classified records. Surname+initial parsing cannot fully disambiguate
authors with identical names, so interpret clusters as exploratory. The current
repository does not implement the manuscript's Sankey analysis. Claims depending on that procedure need separate
reproducible analyses or revision of the manuscript.
Country SCP/MCP rates are also exported with 95% Wilson intervals for
country-category groups with at least 10 identified records. The RCA workbook
includes 95% document-bootstrap intervals (1,000 replicates; seed 20260929);
these are exploratory uncertainty estimates and do not correct for potential
classification or affiliation-parsing error.

## Reviewer Issues — Correspondence

This repository was restructured in response to peer-review feedback.
The table below maps each reviewer issue to its resolution.

| Reviewer Issue | Resolution |
|----------------|-----------|
| Four-way technology rules and overlap | Implemented in the canonical classifier and output with a per-record term trace; still requires human validation and explicit MR/XR rationale in the manuscript |
| Technical/pedagogical reproducibility | Keyword scoring and tie rule are explicit; the result is highly imbalanced (99.3% Pedagogical), so interpret the orientation analysis as exploratory |
| Corpus flow | DOI, normalized-title, metadata, thematic, year and category counts are exported stage by stage; normalized-title match is exact, not fuzzy |
| Education construct operationalization | Implemented a deterministic binary lexical eligibility rule over Title, Abstract, and Author Keywords; counts and per-record matched cues are regenerated on each run. The manuscript must describe the operational rule and acknowledge possible lexical false negatives/positives |
| SCP/MCP inconsistency | Country parsing is centralized in `utils/countries.py`; unparseable addresses are Unresolved and excluded from SCP/MCP denominators |
| Network robustness | Co-authorship, keyword, and author co-citation networks have explicit thresholds and sensitivity outputs. Author identity disambiguation and community stability remain limitations |
| Reviewer issues requiring manuscript/human work | Inter-rater agreement, 2025 retrieval completeness, implications/contribution, causal claims, and manuscript formatting cannot be established by these scripts alone |
